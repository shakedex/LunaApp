# Luna Web — Plan 01: Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the `web/` Bun-workspace monorepo so the app boots behind a capability gate, `packages/core` runs a green `bun test`, the Starlight docs site builds, and CI is green.

**Architecture:** A Bun workspace under `web/` with three packages: `app` (Vite + React + TanStack Router + Tailwind v4 + shadcn/ui SPA), `docs` (Astro Starlight, base path `/docs`), and `packages/core` (pure TypeScript, DOM-free, unit-tested with `bun test`). This plan builds only the scaffolding and the capability gate; no media, decode, or export logic yet.

**Tech Stack:** Bun, TypeScript (strict), Vite, React 19, TanStack Router, Tailwind CSS v4, shadcn/ui, Astro Starlight, Biome, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-07-17-luna-web-design.md` (see §6 repo layout, §7 stack, §8.1 capability gate, §17 testing, §18 deploy).

## Global Constraints

- **Runtime / package manager / task runner:** Bun. No pnpm, no npm scripts run through Node.
- **Unit tests:** `bun test` only. No Vitest. No Playwright. No automated UI/e2e tests.
- **Language:** TypeScript `strict: true` everywhere.
- **Lint + format:** Biome (single tool). No ESLint, no Prettier.
- **`packages/core` is DOM-free:** no `window`, `document`, DOM types, or browser globals. Node/bun-testable in isolation.
- **Target browser:** Chromium only (File System Access API). Non-Chromium gets a capability gate, never a broken app.
- **No cross-origin isolation:** do not add COOP/COEP headers or `SharedArrayBuffer` usage.
- **Open-source project.** Permissive deps; the only non-permissive dependency (GPL ffmpeg core) arrives in a later plan, not this one.
- **Publish target:** `luna.ozer2.one`; docs served at the `/docs` path (Starlight `base: '/docs'`). Wrangler/deploy config is a later plan — not here.
- **The existing .NET app at the repo root is never touched.** All work is under `web/`.

```ts
export const SUPPORTED_MEDIA_EXTENSIONS = [
  '.mov', '.mp4', '.mxf', '.avi', '.mkv', '.m4v',
  '.mts', '.m2ts', '.3gp', '.webm', '.wmv', '.flv',
] as const

export const UNSUPPORTED_RAW_EXTENSIONS = ['.r3d', '.braw', '.ari'] as const

function extensionOf(fileName: string): string {
  const dot = fileName.lastIndexOf('.')
  return dot === -1 ? '' : fileName.slice(dot).toLowerCase()
}

export function isSupportedMediaExtension(fileName: string): boolean {
  return (SUPPORTED_MEDIA_EXTENSIONS as readonly string[]).includes(extensionOf(fileName))
}

export function isKnownRawExtension(fileName: string): boolean {
  return (UNSUPPORTED_RAW_EXTENSIONS as readonly string[]).includes(extensionOf(fileName))
}
```

## Task 4: Capability gate

**Files:**
- Create: `web/app/src/lib/capabilities.ts`, `web/app/src/components/capability-gate.tsx`
- Modify: `web/app/src/routes/__root.tsx`

**Interfaces:**
- Consumes: nothing outside the app.
- Produces:
  - `interface Capabilities { fileSystemAccess: boolean; webCodecs: boolean; wasm: boolean }`
  - `detectCapabilities(): Capabilities`
  - `isBrowserSupported(c: Capabilities): boolean` — true only when `fileSystemAccess && wasm` (WebCodecs is a bonus, not required — the ffmpeg path covers its absence).
  - `<CapabilityGate>` — renders children when supported, else a full-screen explainer.

- [ ] **Step 1: Create `app/src/lib/capabilities.ts`**

```ts
export interface Capabilities {
  fileSystemAccess: boolean
  webCodecs: boolean
  wasm: boolean
}

export function detectCapabilities(): Capabilities {
  return {
    fileSystemAccess: typeof window !== 'undefined' && 'showDirectoryPicker' in window,
    webCodecs: typeof window !== 'undefined' && 'VideoDecoder' in window,
    wasm: typeof WebAssembly !== 'undefined',
  }
}

// File System Access + WASM are required. WebCodecs is optional: when absent,
// every clip decodes through the ffmpeg.wasm path (spec §8.1, §10.2).
export function isBrowserSupported(c: Capabilities): boolean {
  return c.fileSystemAccess && c.wasm
}
```

- [ ] **Step 2: Create `app/src/components/capability-gate.tsx`**

```tsx
import { type ReactNode, useMemo } from 'react'
import { detectCapabilities, isBrowserSupported } from '@/lib/capabilities'

export function CapabilityGate({ children }: { children: ReactNode }) {
  const supported = useMemo(() => isBrowserSupported(detectCapabilities()), [])

  if (supported) return <>{children}</>

  return (
    <main className="flex min-h-screen flex-col items-center justify-center gap-4 bg-zinc-950 px-6 text-center text-zinc-100">
      <h1 className="text-2xl font-semibold">Luna Web needs a Chromium browser</h1>
      <p className="max-w-md text-zinc-400">
        Luna Web reads your footage folder directly on your device using the File System
        Access API, which is available in Chrome, Edge, and other Chromium browsers. Please
        open this page in one of those to continue. Nothing is ever uploaded.
      </p>
    </main>
  )
}
```

- [ ] **Step 3: Wire the gate into the root route** — replace `app/src/routes/__root.tsx`
